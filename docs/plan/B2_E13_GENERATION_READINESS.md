## 3. What E13 implements

`scripts/b2_e13_generation_plan.py` and `tests/test_b2_e13_generation_plan.py`, plus one additive change to the read-only `scripts/b2_host_inventory.py` (each disk row now reports its filesystem type; the report carries the node name and a collection time) so that a volatile or pseudo filesystem and a stale or foreign host report can be refused by machine. No file under `src/`, `configs/`, `.github/` or `pyproject.toml` changes, so the source hashes the lock and every checkpoint record are **unchanged** (unlike E9, which added a `src` module). The script lives in `scripts/` like the E12 K17d verifier.

* `collect_reference(...)` reads sources, configs, gates, memorandum, decision register, K17d identity and audit, and the scientific protocol record, and asks read-only `git` (an injectable callable, run with `core.fsmonitor=false`) for HEAD, for the cleanliness of the **whole** tree (`status --porcelain --untracked-files=all`) and, for each input and each cited authorization record, whether it is a regular, non-symlink, tracked file whose working-tree blob equals HEAD's. It computes the known-stage request fingerprint the generator would write (`b2_dataset._request`, no synthesis) and takes the snapshot twice, refusing a checkout that changed in between. The report carries the snapshot's SHA-256.
* `make_template(reference)` derives a plan skeleton from the checkout. Host, backup, lock, release evidence and authorization are deliberately `null`; ceilings are the E5 proposals marked `PROPOSED_NOT_APPROVED`.
* `validate_plan(plan, reference)` returns a strict-JSON report with 40+ identified findings (`PASS`, `FAIL`, `BLOCKED`). **The verdict is always `NO-GO`, `execution_permitted` is always false.** `plan_status` can read `DOCUMENT_CONSISTENT_NOT_A_PERMISSION`, a statement about a document only; `counts` include the structural blockers. Four structural blockers (launch flag, no unbounded launcher, fixture cap, E9 guard) are re-evaluated on each call and cannot be satisfied by any document; if one is changed, the report says `FAIL` and stays NO-GO.
* Exit codes: 2 usage/input error, 3 inconsistent plan, 4 NO-GO. There is no exit 0 for `status`/`validate`.
* The module imports no process-creation facility, has no argv builder, no callback and no execute flag, and its tests assert that (AST scan, command-line refusal, patched `subprocess`/`os`/generators/array loading around `validate_plan` and `collect_reference`). Reference collection runs read-only `git` through the injectable callable; with `--lock` the preflight's lock builder also runs `git` and `uname`. Nothing in this path runs a generator.

## 4. Observations about existing code (recorded, not changed)

1. **The gates JSON is part of the lock.** `LOCKED_CONFIGS` includes `docs/plan/b2_readiness_gates_2026-10-21.json` (`preflight:57`). Recording the DR-04 approval in the gate changes that hash and invalidates any lock created earlier. Order: record the approval, commit, **then** create the lock, then bind the plan to it.
2. **Test-only and matched request fingerprints exist only after the known stage.** Their requests embed the known artifact's data fingerprint (`b2_test_dataset._known_binding`). The plan can fix the known-stage request now; the later two must be verified at their stage boundary by the supervisor.
3. **`supervisor.authorization` is structural.** It accepts any well-formed approval in four gates; it does not look at a plan, commit, host or ceilings (E8 test documents this). E13's binding is a validation layer, not a change to it.
4. **No backup control in the supervisor or preflight.** The check exists only as a report in `b2_host_inventory.py`. On this sandbox it "passes" a tmpfs path (`/dev/shm`, a different device) as a backup, which shows why a different `st_dev` is necessary but not sufficient. The E13 validator therefore also refuses volatile trees (`/dev`, `/proc`, `/sys`, `/run`, `/tmp`, `/var/tmp`), volatile/pseudo/overlay filesystem types (now reported by the inventory), roots that were not measured themselves and nested roots.
5. **Two meanings of "25 GiB working disk".** Preflight: free >= 25 GiB. Supervisor: free >= `1.1 x 21,350 x 406,000 B` + 25 GiB, about 33.9 GiB. A host sized to the first fails the second.
6. **No fsync in generator commits** (`dataset.py:124`; `np.savez` temporary files). Detected by the checksum audit rather than prevented.
7. **No immutability enforcement** after verification; E12 states immutable artifact directories are assumed.
8. **`preflight.environment()` spawns `uname`** through `platform.platform()`; E13 avoids it so its own path has no subprocess.
9. **Stale `main_training_gpu_hours: 6`** remains in `scripts/b2_production_preflight.py:78` (E11-B finding; irrelevant to generation, unchanged).
